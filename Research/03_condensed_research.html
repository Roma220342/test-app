Everything useful, no water

The whole discovery pass on one page — for when you don't have time to open the dossier.

What: Redesign the MUI (Management User Interface) — the web admin console for Wonderline's Loyalty on Demand (LOD) platform. Powers Shell's ~9M-customer program; now going to market.

Who for: the client's own non-technical marketing & customer-service teams — not Wonderline staff, not end customers.

The trial: redesign the Campaign / Offer Configuration wizard (Target → Trigger → Validity → Benefit → Offer Details). 3–5 days, to win a longer engagement.

Win condition: make their most complex, most-demoed screen feel simple, modern, and self-serve — while keeping an advanced mode for complex Shell offers.

01 The two users

Primary

Marketing Manager (client-side, e.g. Shell)

  • Non-technical; wants to launch offers without asking IT.
  • Broad access to campaigns + customer data.
  • Frustrated by jargon, dense menus, and a UI that feels 20 years old in front of prospects.
  • "Good" = a guided, plain-language flow with sensible defaults.
Secondary

Customer-Service Agent + Power User

  • CS: very limited access — only customers + their transactions.
  • Power user / analyst: sets up complex Shell offers, needs the advanced mode kept.
  • Tension to design for: simple by default, powerful on demand.

02 What they want (in their words)

“We want marketing people without IT support to use our product.” · “Simple, but still handling complex environments and systems.” · “The product does not look like 20 years ago.” · Keep an advanced mode “if anybody wants to go into details.”

05 Patterns to steal (per step)

  • Live audience reach in Target. Show estimated segment size as you build (sampled at 9M scale). — Klaviyo / Braze live segment size. Their own AI mockup already wants this ("87,220 matching").
  • AND/OR rule builder with chips for dynamic segments; flat/AND-only for novices, nested OR groups reserved for Advanced. — Braze / query-builder pattern.
  • Blur-based inline validation (validate on leaving a field, not on every keystroke) — kills the wall-of-red. — Baymard / Material.
  • Persistent live preview rail — elevate the existing Offer Summary into a signature component. — Mailchimp / Dynamics preview + test.
  • Progressive disclosure + smart defaults — every step opens with a sane default; complexity appears only when chosen. — tiered-controls pattern.
  • Basic ↔ Advanced handoff that carries state — opt-in escape hatch, nothing lost. — expert-mode pattern; the "Advanced Setup" button already exists.

White-dominant, red/black/gray. The one rule that changes everything: split brand red (CTA/active only) from a calm "selected" state and a distinct semantic error — so a chosen option stops looking broken. Type: clean enterprise sans (Inter / IBM Plex), tabular figures for tables & points.

07 Design principles

  1. Clarity over cleverness — if their own team can't explain a control, a marketer can't use it. Plain language wins.
  2. Calm by default — colour carries meaning, not decoration; red is earned, not everywhere.
  3. Show the consequence — live reach, live summary, live preview. Never make the user guess.
  4. Simple surface, powerful underneath — defaults for novices, an honest advanced path for experts.
  5. Enterprise-credible — every screen should say "handles millions of customers" without shouting it.
  6. Respect the constraints — Java + limited design system + QuickSight fixed; design what can ship.
  7. Demo-ready — it has to look great in a prospect conversation, first glance.
Don't: gamify the admin tool (never requested) · use red for selection/validation/CTA all at once · gate audience size behind a modal · rename to internal jargon · rebuild the IA (it's fine) · hard-commit visuals before the rebrand lands · scope-creep past the wizard.
